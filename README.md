# Вариант 17. Кухня ресторана

Курсовой проект по ПМ.02: виртуальная система сбора и учёта данных на Arduino Uno.

Система контролирует уровень газа, температуру и влажность.
При уровне газа выше 40 % включаются реле вытяжки и жёлтый светодиод.
Показания и события передаются через текстовый лог в Node-RED
и сохраняются в базе данных SQLite.

## Входные данные

Вариант — 17.
Сценарий — кухня ресторана.
Микроконтроллер — Arduino Uno.
Датчик s1 — MQ2, уровень газа, диапазон 0–100 %.
Датчик s2 — NTC, температура, диапазон −20…80 °C.
Датчик s3 — DHT22, влажность, диапазон 0–100 %.
Исполнительное устройство — реле управления вытяжкой.
Светодиод — жёлтый, заданный ток 15 мА.
Резистор светодиода — 200 Ом.
Период измерений — 1 секунда.
Условие включения реле и светодиода — газ выше 40 %.
Условие выключения — газ не выше 40 %.

Аналоговые показания преобразуются по учебной линейной шкале
из задания. Уровень газа выражается в процентах, а не в ppm.
Температура NTC в журнале может отличаться от температуры
в настройках датчика Wokwi.

При использовании подготовленного скетча библиотека DHT22
обновляет влажность примерно раз в 2 секунды, поэтому при
выводе DATA каждую секунду соседние значения могут совпадать.

## Порядок запуска

1. Убедиться, что Node.js, Node-RED и SQLite установлены,
   а команда sqlite3 доступна в окружении запуска Node-RED.
2. Запустить start-nodered.bat из папки проекта.
3. Открыть http://localhost:1880.
4. Если поток ещё не настроен, импортировать nodered/flow.json
   через меню → Импорт.
5. Проверить пути к файлам. Для относительных путей Node-RED
   должен быть запущен из папки проекта. Если в потоке сохранены
   абсолютные пути другого компьютера, заменить их.
6. Нажать «Развернуть».
7. Открыть проект Wokwi по ссылке выше и запустить симуляцию.
8. Скопировать строки DATA и EVENT из Serial Monitor,
   заменить ими содержимое data/log.txt и сохранить файл.
9. Узел watch запустит загрузку автоматически.
   Для ручной загрузки нажать кнопку у узла «метка времени».
10. Проверить отладочные сообщения: команда exec должна
    завершиться с кодом 0 без сообщений об ошибке.
11. В консоли из папки проекта выполнить:

```bat
sqlite3 -header -column db/variant.db ".read db/queries.sql"
```

При каждой загрузке содержимое таблиц заменяется данными
из всего текущего лога. Это не накопление истории разных файлов.

Если db/load.sql уже сформирован, но выполнение команды
через Node-RED не сработало, загрузить его вручную:

```bat
sqlite3 -bail db/variant.db ".read db/schema.sql" ".read db/load.sql"
```

## Формат данных и событий

Пример строки измерения:

```text
DATA n=1 s1=25.00 s2=30.00 s3=50.00
```

- n — номер измерения;
- s1 — уровень газа, %;
- s2 — температура, °C;
- s3 — влажность, %.

При переходе в состояние тревоги скетч выводит
EVENT с типом THRESHOLD, при возврате в норму — NORMAL.
Событие выводится один раз при изменении состояния.

Node-RED формирует FAULT, если значение датчика
выходит за допустимый диапазон.

## Проверка неисправности

В data/log_fault.txt используется строка:

```text
DATA n=1 s1=999 s2=25.0 s3=50.0
```

1. Временно указать data/log_fault.txt в узле чтения файла.
2. Нажать «Развернуть» и запустить загрузку кнопкой
   у узла «метка времени».
3. Проверить событие запросом:

```bat
sqlite3 -header -column db/variant.db "SELECT * FROM events WHERE type='FAULT';"
```

Ожидаемый результат: событие FAULT с сообщением
«датчик s1 вне диапазона».

После проверки вернуть в узле чтения путь data/log.txt,
нажать «Развернуть» и загрузить обычный лог.
Тестовая запись FAULT при этом будет удалена из базы;
результат проверки сохраняется на скриншоте.
